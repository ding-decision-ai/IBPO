# IBPO: Reinforcement Learning with Comparison and Correction

Run all commands from the project root, the directory containing `setup.py`, `verl/`, and `recipe/`. All paths are relative to this working directory. Do not run the commands from inside the `verl/` subdirectory.

## 1. Environment Setup

### Create a New Environment

Install a working NVIDIA driver and uv, then run:

```bash
uv venv --python 3.12 .venv
source .venv/bin/activate
uv pip install --only-binary vllm,torch,xformers -r recipe/ibpo/requirements-reproduction.txt
uv pip install --no-deps -e .
```

### Reuse an Existing GPU Environment

If compatible CUDA-enabled PyTorch and vLLM are already installed, activate that environment and install this package with the following command. There is no need to reinstall or rebuild vLLM:

```bash
uv pip install --no-deps -e .
```

After creating or activating the environment, run:

```bash
export PYTHONPATH="$PWD"
export RAY_ENABLE_UV_RUN_RUNTIME_ENV=0
export VLLM_USE_FLASHINFER_SAMPLER=0
export TOKENIZERS_PARALLELISM=false

uv pip check
python -c "import torch, vllm, verl; print(torch.__version__, vllm.__version__, verl.__file__); assert torch.cuda.is_available()"
```

## 2. Models

During training, both primary responses and correction responses are generated by the same frozen old policy. A single joint optimizer update is performed after all correction sampling is complete.

## 3. Prepare Training Data

The paper uses DeepMath-103K and OpenCodeReasoning. This package does not include the original training datasets or their original mixture split. Prepare data you are authorized to use and convert it to the verl Parquet format shown below. Only questions and reference answers or test cases for terminal verification are required; do not use the original datasets' long responses directly as RL training targets.

Example math record:

```json
{"prompt":[{"role":"user","content":"Compute 1+1. Put the final answer in \\boxed{}."}],"data_source":"DigitalLearningGmbH/MATH-lighteval","reward_model":{"style":"rule","ground_truth":"2"},"extra_info":{"index":0}}
```

Here, `data_source` selects the math terminal verifier; it does not necessarily identify the dataset from which the training example originates. This verifier extracts the final boxed answer. Keep the model prompt and `ground_truth` consistent with your data format. The original DeepMath source name cannot be used directly unless a corresponding verifier has been registered.

Convert JSONL records with the structure above to Parquet. For a full training run, provide enough records to form a complete batch of original prompts:

```bash
mkdir -p data
python - <<'PY'
import json
from pathlib import Path
import pandas as pd

for split in ("train", "val"):
    rows = [json.loads(line) for line in Path(f"data/{split}.jsonl").read_text().splitlines() if line.strip()]
    assert rows and all({"prompt", "data_source", "reward_model"} <= row.keys() for row in rows)
    pd.DataFrame(rows).to_parquet(f"data/{split}.parquet", index=False)
PY
```

`val` should be an independent held-out split from the training data source. Code tasks require complete executable test cases and a corresponding verifier; a reference-program string alone is insufficient for correctness verification. Use `reward.custom_reward_function.path/name` to provide a custom binary reward function that returns `score` and `acc` fields, each either `0` or `1`. Unknown data sources raise an error rather than triggering an automatically inferred scoring rule.

## 4. Run Training

Place the model in `models/Qwen3-32B` and the training and held-out datasets in `data/` as described above. The example below uses 32 GPUs across four nodes, with eight GPUs per node. Install the same environment on every node and use identical code, model, and data paths.

```bash
# On the head node, replace HEAD_NODE_IP with its address reachable from the other nodes.
ray start --head --node-ip-address=HEAD_NODE_IP --port=6379 --num-gpus=8

# Run this command on each of the other three nodes.
ray start --address=HEAD_NODE_IP:6379 --num-gpus=8
```

From the project root on the head node, run:

```bash
export RAY_ADDRESS=auto
python -m recipe.ibpo.main_ibpo --config-name=ibpo_trainer \
  actor_rollout_ref.model.path=models/Qwen3-32B \
  data.train_files=data/train.parquet \
  data.val_files=data/val.parquet \
  actor_rollout_ref.rollout.tensor_model_parallel_size=1 \
  actor_rollout_ref.rollout.temperature=1.0 \
  actor_rollout_ref.rollout.top_p=1.0 \
  actor_rollout_ref.rollout.top_k=-1 \
  actor_rollout_ref.rollout.val_kwargs.temperature=1.0 \
  actor_rollout_ref.rollout.val_kwargs.top_p=0.7 \
  actor_rollout_ref.rollout.val_kwargs.top_k=-1 \
  actor_rollout_ref.rollout.val_kwargs.do_sample=true \
  actor_rollout_ref.rollout.val_kwargs.n=1 \
  trainer.nnodes=4 trainer.n_gpus_per_node=8 \
  trainer.total_epochs=1 trainer.val_before_train=true \
  trainer.test_freq=100 trainer.save_freq=100 \
  trainer.resume_mode=disable trainer.logger='[console,file]' \
  trainer.default_local_dir=checkpoints/ibpo-fixed \
  actor_rollout_ref.actor.checkpoint.save_contents='[model,optimizer,extra,hf_model]'
```
Resumable training shards and Hugging Face models are saved in `checkpoints/ibpo-fixed/global_step_*/actor/`.

For the Next model, use `--config-name=ibpo_qwen3next` and replace the model path with your Next model directory. Choose the parallelism layout to match your actual cluster.

Variants: for ratio, add `ibpo.variant=ratio ibpo.shaping_weight=0.4`; for mask, add `ibpo.variant=mask ibpo.mask_fallback=unmasked`, or explicitly select `skip`. Disable auxiliary training with `ibpo.aux_weight=0`. When `G_c=1`, the within-group auxiliary advantage is zero.
